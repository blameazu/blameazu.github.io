intro
#

這篇打算寫的很淺顯易懂(應該)

之前寫過的講義:

  • 高二寫的
  • 高三寫的

複雜度要拿來幹嘛的?
#

當今天我們寫一份 code，丟上去 OJ，結果發現 TLE 了，這樣我們就意識到我們的 code 執行速度太慢太慢了。

但我們只能透過 online judge 告訴我們我們寫太慢，還是我們可以自己評估、判斷出自己寫的 code 的執行速度大概多快呢?

假如我們今天有一個可以判斷 code 執行速度的方法，那麼我們是否可以先在丟上 judge 或甚至開始寫 code 前就判斷出我的算法、寫法是否可以通過題目?

時間複雜度 (Time Complexity) 就是一個可以大致判斷一個程式 執行速度 的方法。

怎麼形容一個程式的速度?
#

對於一個程式，通常他執行的速度跟他的輸入量大小有關。

舉個例子

Problem
輸入一個正整數 $n$，輸出 $1 + 2 + \ldots + n$ 等於多少

假設我採取的方法是

  • 輸入一個數 $n$
  • 新增一個變數 $ans$，初始值為 $0$
  • 使用 for-loop 從 $1$ 遍歷到 $n$(Let $i$ := $1 \ldots n$)，每個數字都加到 $ans$ ($ans = ans + i$)
  • 輸出 $ans$

那麼當我輸入 $n = 3$ 與 $n = 87$，兩個執行時間肯定有差，因為後者會跑差不多 $87$ 次迴圈。

那麼也就是說程式的執行速度其實就像是根據輸入量變化的函式。

像是剛剛我們採取的方法，執行速度可以寫成多項式 $(\text{執行速度} = n)$

當輸入量提高，那麼執行速度變慢;輸入量減少，執行速度變快。

漸進符號
#

但當程式越來越複雜後

我們要把精確的執行次數、速度的函式寫出來根本是不可能的

所以我們想要將這個函式做一個估計、大概

我們引入了 漸進符號 $O$

$O$ 的數學定義
$f(n) = O(g(n)) \Leftrightarrow \exists \space n_0, c > 0, s.t. \forall \space n \ge n_0, f(n) \le c \cdot g(n)$

數學式依舊抽象，我們可以看一下幾何意義

假設 $f$ 是我們程式實際跑起來的輸入，底下這張圖代表著 $f$ 對於不同輸入量大概會長怎樣

而有一個 $g$ 線性函式長這樣

把他乘上某個神奇的常數 $c$ 後，對於某一個點開始，後面的所有 $n$ 來講都有著 $g(n) \ge f(n)$ 的性質

那麼我們就稱 $f(n)$ 函式漸近 $g(n)$ 函式。

當 $n$ 拉大的時候，$f(n)$ 將會被 $g(n)$ bounded 住，所以我們只要確保 $g(n)$ 是可接受的，那麼 $f(n)$ 自然也可接受了。

假如上面這邊還是有點沒聽懂，那我再講直白一點。

就是我的程式的執行速度為 $f(n)$，但 $f(n)$ 長太醜了，我想要找一個寬鬆的上界 $g(n)$，使得 $g(n) \times c$ 可以完美的包住 $f(n)$。

$O$ 的性質
#

  1. 忽略常數

我們發現 $g(n)$ 中的常數我們都可以丟掉。

因為對於 $g(n) + a$、$g(n) \times a$ 來講，最後還是會乘上常數 $c$ 來判斷 $f(n)$ 是否小於 $c \cdot g(n)$

那麼我們想要讓 $g(n)$ 變得好看、好算，所以我們通常都直接省略 $g(n)$ 的一切常數。

  1. 只在意最高項次

假如 $g(n) = n^2 + n + 1$ (已經將常數都省略了)

那麼我們會發現 $g(n)$ 可以只寫最高項次，$g(n) = n^2$

我們發現當 $n$ 變得超級超級大的時候，$n^2$ 遠大於 $n$，所以 $n$ 對於 $g(n)$ 的貢獻會相對來說變的超級少，甚至可以忽略。

真正來試試看
#

Problem
  • 輸入一個正整數 $n$
  • 新增一個變數 $ans$
  • 用 for-loop 從 $1$ 跑到 $n$，對於所有遍歷到的數字，$ans$ += 那個數字的平方
  • 輸出 $ans$
複雜度多少?
$O(n)$
Problem
  • 輸入一個正整數 $n$
  • 用 for-loop 從 $1$ 跑到 $n$，每次輸入一個整數 $a$，假如 $a = 67$ 那麼直接跳出這個 for-loop，否則繼續執行下個迴圈
複雜度多少?

$O(n)$

因為當 $a$ 永遠不等於 $67$ 的時候，迴圈會跑 $n$ 次。

(也就是在這個時間複雜度我們在意的是最糟的情況)

Problem
  • 輸入一個正整數 $n$
  • 輸出 $1 \sim n$ 每個數字佔一行
  • 輸出 $n \sim 1$ 每個數字佔一行
複雜度多少?

$O(n)$

雖然實際上等於 $O(2n)$，但我們省略常數，所以變成 $O(n)$

Problem
  • 輸入一張 $n \times n$ 的地圖
  • 輸出 $1 \sim n$，每個數字佔一行
複雜度多少?

$O(n^2)$

輸入地圖 $O(n^2)$

輸出 $O(n)$

總共 $O(n^2 + n)$

取最高項，所以是 $O(n^2)$

Problem
  • 輸入一張 $n \times m$ 的地圖
複雜度多少?

$O(nm)$

對於多個輸入量，我們無法確保哪個輸入量比較大，所以都保留

當 $m \le n$ 的時候，複雜度可以寫成 $O(n^2)$

多少的複雜度可以通過題目
#

現在的電腦大多 $1s$ 可以跑 $5 \cdot 10^8$ 次操作

也就是你的複雜度 $O(g(n))$ 代 $n$ 進去 $\le 5 \cdot 10^8$ 應該可以過。

常見複雜度
#

以下都先討論單個輸入量 $n$

對於輸入量 $n$ 的大小，最糟的 $g(n)$ 差不多可以長怎樣?

  • $n \le 10^6$ : $O(n)$
  • $n \le 10^5$ : $O(n \log n)$
  • $n \le 10^4$ : $O(n^2)$
  • $n \le 10^2$ : $O(n^4)$
  • $n \le 20$ : $O(2^n)$
  • $n \le 10$ : $O(n!)$

賽中背不起來可以直接把題目給的範圍最大代數字進去，差不多 $\le 5 \cdot 10^8$ 應該就會過。

舉個例子
#

Problem

給你一個正整數 $n$

再給你一個長度為 $n$ 的陣列 $A$

請你輸出陣列 $A$ 由小到大排序過後長怎樣

$n \le 3000, A_i \le 3000$

聰明的你，馬上想到國小電腦老師教過的 bubble sort

  • for-loop $i := 1 \sim n-1$，假如 $A_i > A_{i+1}$，那麼交換 $A_i, A_{i+1}$
  • 重複執行前面那個動作，直到沒有交換發生。
複雜度多少?

$O(n^2)$

發現 $3000^2 \le 5 \cdot 10^8$，所以會過。

但當 $n \le 10^6$ 的時候，你的算法就不會過了…。

也就是說當 $n = 10^6$ 的時候，你把 bubble sort 丟上去 OJ 上一定會拿到 TLE!

這時候就得改個作法了。

更快的做法理論上就不是這篇文想講的東西了。

總結
#
